## Findings

[CLN-001]

**Issue:** In `src/components/recipes/__tests__/RecipeEditor.spec.ts`, the new test `stays disabled when an ingredient name is only spaces` verifies that `save-button` stays disabled, which happens because `IngredientEditorRow`'s `v-text-field` fails `validationRules.required` and sets `v-form`'s `valid` state to `false`. It does not directly exercise `isValidIngredient` in `src/components/recipes/RecipeEditor.vue` (which controls the `SortableListEditor` `validateItem` prop / `add-ingredient-button`, `disableNutritionButton`, and the save filter). If `item.name?.trim()` in `isValidIngredient` were reverted to `item.name`, all tests in `RecipeEditor.spec.ts` would still pass.  
**Suggestion:** Also assert that `add-ingredient-button` (or `calculate-nutrition-button` when no other valid ingredients exist) is disabled when an ingredient has `units`, `unitOfMeasure`, and a whitespace-only `name`:

```typescript
it('disables adding another ingredient when an ingredient name is only spaces', async () => {
  const addIngredientButton = wrapper.find('[data-testid="add-ingredient-button"]');
  const opened = BEER_CHEESE.ingredients[2]!;
  const ingredients = wrapper.find('[data-testid="ingredient-list-grid"]').findAllComponents(IngredientEditorRow);
  await ingredients[2]?.vm.$emit('changed', { ...opened, name: '   ' });
  expect(addIngredientButton.attributes('disabled')).toBeDefined();
});
```

**Why:** Directly guards the `item.name?.trim()` check in `isValidIngredient` against regressions.

[CLN-002]

**Issue:** In `src/components/recipes/RecipeEditor.vue`, `createRecipeFromForm` filters and trims `ingredients` and `steps` (lines 375–382), while `nutritionPromptFromForm` (lines 431–432) still passes `ingredients.value.filter(isValidIngredient)` and `steps.value.filter(isValidStep)` without trimming `name` and `instruction` (even though `nutritionPromptFromForm` already trims the recipe `name` and `description` on lines 421–422).  
**Suggestion:** Extract small helpers for the filtered and trimmed lists and reuse them in both `createRecipeFromForm` and `nutritionPromptFromForm`:

```typescript
const validTrimmedIngredients = (): RecipeIngredient[] =>
  ingredients.value.filter(isValidIngredient).map((ingredient) => ({
    ...ingredient,
    name: ingredient.name.trim(),
  }));

const validTrimmedSteps = (): RecipeStep[] =>
  steps.value.filter(isValidStep).map((step) => ({
    ...step,
    instruction: step.instruction.trim(),
  }));
```

**Why:** Eliminates duplicate filtering logic and keeps the recipe payload sent to `generateNutritionData` consistent with the recipe payload emitted on save.

[POS-001]

**Issue:** Whitespace handling in `src/components/recipes/RecipeEditor.vue` across dirty-checking and save payload construction.  
**Suggestion:** `ingredientAtIndexDiffers`, `stepAtIndexDiffers`, and `createRecipeFromForm` align cleanly with the existing `name.value.trim()` pattern on `RecipeEditor.vue`, ensuring that adding leading or trailing spaces neither enables the Save button prematurely nor persists untrimmed strings.  
**Why:** Keeps form dirty-tracking predictable and consistent across all text inputs in the recipe editor.

[POS-002]

**Issue:** Test coverage in `src/components/recipes/__tests__/RecipeEditor.spec.ts`.  
**Suggestion:** The new test cases cover surrounding spaces on unchanged values, whitespace-only values, trimmed values emitted on save, and preservation of internal spaces (`'Chopped  Onion'`).  
**Why:** Gives clear confidence that surrounding whitespace is stripped while intentional internal spacing is preserved.
